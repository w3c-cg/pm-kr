# Procedural Memory Knowledge Representation Community Group

This repository is being used for work in the W3C Procedural Memory Knowledge Representation Community Group, governed by the [W3C Community License Agreement (CLA)](http://www.w3.org/community/about/process/cla/).
To make substantive contributions, you must join the CG.

If you are not the sole contributor to a contribution (pull request), please identify all contributors in the pull request comment.

To add a contributor (other than yourself, that's automatic), mark them one per line as follows:

```
+@github_username
```

If you added a contributor by mistake, you can remove them in a comment with:

```
-@github_username
```

If you are making a pull request on behalf of someone else but you had no part in designing the feature, you can remove yourself with the above syntax.


## Drafting and reviewing public material

Use the [document guidance and practical checks](reports/README.md) appropriate to the artifact. Explain the user problem, distinguish proposals from measured results, preserve actual document status and link public evidence. Keep historical correspondence and meeting records intact. Participation or an outreach reply does not imply an organization's endorsement.

You may explain your contribution in your preferred language. AI partners can help prepare an English draft; authors remain responsible for the meaning, evidence and attribution. If it is easier for you, you can explain in your own language. Se for mais fácil para você, pode explicar em sua própria língua.

For ReSpec report edits, run `npm run check:reports` with the standalone respec-mcp checkout beside this repository. Review the policy diff as well as the document diff. Markdown explainers and other artifacts need editorial review using the corresponding skill; a ReSpec pass does not validate those documents.
